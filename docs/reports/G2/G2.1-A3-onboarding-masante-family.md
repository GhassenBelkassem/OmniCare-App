## 3. Decisions

### 3.1 « Ma Santé » and the family screen share A2's editor logic
Both open the same `EditMedicalDataScreen`, which now takes a `MedicalDataEditorViewModel`. That is the A2 view model, created by the `MedicalDataEditorFactory` in `main.dart`: `SelfRecordSubject` from Ma Santé, `FamilyRecordSubject(member.id)` from the family screen. So every A2 rule applies unchanged:
- only changed sections, one `SaveAttempt` each;
- professional items are never sent;
- no A+ default, and « Je ne sais pas » is `UNKNOWN`;
- a 409 reloads only that section and keeps what was typed;
- « Réessayer » sends the same content with the same key;
- the same French texts.

The screen keeps its layout. Only what it is bound to changed:
- **Loading:** it reads the record first (loading / failure + « Réessayer », the record cards' block), then fills the fields once. A later read never replaces what was typed.
- **Blood type:** the same dropdown with one more entry, « Je ne sais pas » (A2 rule). « - » means nothing chosen and is never sent. A blood type set by a professional shows in a disabled dropdown.
- **Conditions:**
  - The same chips. The list now comes from A2's one constants file, so « Allergie Pénicilline » is no longer a condition preset (D2, §5.3).
  - The patient's own conditions that aren't presets now show as chips. Before, they were invisible, and they were still kept.
  - A professional condition shows as chosen; tapping it shows « Cet élément a été ajouté par un professionnel de santé… » and changes nothing.
  - `critical` is never sent (D6, B6b).
- **Medications:**
  - Own declared items are editable: free-text name (the search field stays, but its suggestions never block), dose, « Fréquence ».
  - Each row shows « Déclaré par le patient » (ARB, the card's label style).
  - OmniCare prescriptions are shown read-only with the Résumé row (`PassportMedicationRow`, reused) and never sent.
  - Duration and start date have no field here and are kept as read.
- **« Fréquence » text → `timesPerDay`:**
  - empty → not given;
  - « 2 », « 2x/jour », « 2× par jour », « 2 fois par jour » → 2;
  - anything else → refused with « Entre 1 et 6 prises par jour. ». Nothing is guessed.
  - A stored value shows as « 2x/jour », and an untouched row reads back the same, so it isn't sent.
- **Height, weight, allergies:** no field on this screen. The draft carries the record's own values, so those sections are never sent (`editMedicalDataDraft`).
- **Errors:**
  - field messages under the medication fields (input error style);
  - every other failure shows in the screen's existing red SnackBar, now with a « Réessayer » action that resends with the same keys;
  - the screen stays open with everything typed.
- **After closing:**
  - Ma Santé reloads the profile and the « Dossier médical » record if anything saved.
  - The family screen shows what was saved, as it did before for the blood type, now also conditions and medications.
  - The documents block stays local, as before (A4).

### 3.2 Onboarding body page through the record
`_saveBody` now:
- reads `GET /me/medical-record/medical-data` (SELF) for the versions;
- then sends `PUT …/life-safety/blood-type` and/or `PUT …/body-measurements`, only what changed, each with its own `SaveAttempt` (a retry of the same content reuses the key).

Unchanged:
- the 1a-2b guard: « Je ne sais pas » never erases a stored blood type;
- the resume logic.

`OnboardingProgressController` and `ConversationalOnboardingScreen` get the two repositories by constructor injection (`main.dart`). A blood type set by a professional shows « Votre groupe sanguin a été renseigné par un professionnel de santé. »; a conflict and a save in progress show their A1 texts.

### 3.3 Onboarding steps 2–4 (routes kept, content fixed)
- **Step 2:** allergies as typed; « Non » → `noKnownAllergies`. « Oui » with no allergy named is refused with « Indiquez le nom de l'allergie. ».
- **Step 3:**
  - each condition is sent with the French label the patient picked (`onboardingConditionLabel`), never the internal key;
  - `criticalOptIn:false`, so the server stores it not critical (D6, B6b);
  - « Non » → `noKnownConditions`;
  - « Oui » with none chosen → « Choisissez au moins une maladie, ou répondez « Non ». » (new ARB key).
- **Step 4:**
  - `{noKnownMedications:true}`, the only answer the page can give;
  - the dead medication-row code is removed (controllers, catalog check, the fixed « 1x daily », `OnboardingDraft.today` and `medications`).

### 3.4 Onboarding checks mirror the server (`onboarding_validation.dart`, pure)
| Page | Before | Now (same French wording style) |
|---|---|---|
| Body | height 0 < h < 300, weight 0 < w < 500 (« Indiquez une taille valide. ») | height 30–300 cm, weight > 0 and ≤ 500 kg, with the record's texts « La taille doit être comprise entre 30 et 300 cm. » / « Le poids doit être compris entre 0 et 500 kg. » |
| Allergies | name if « risque vital », severity if named | the same, plus at least one if « Oui », ≤ 160 characters, no control or direction character, no duplicate (any case), ≤ 50 |
| Conditions | none | at least one if « Oui »; the same label rules |

Every onboarding message was already French ARB (G3-ONB2); a test checks no English word is left. The 5 ARB keys that no code uses any more are removed (`conditionsAndTreatmentsNotSaved`, `onboardingErrorHeightInvalid`, `onboardingErrorWeightInvalid`, `onboardingErrorMedicationSelect`, `onboardingErrorMedicationDosage`); the ARB contract test requires it. One key is added (`onboardingErrorConditionRequired`).

## 5. ⚠️ Points that need you

1. **STOP: onboarding medications have no place on screen.** The medications page has no fields: « Oui » shows « bientôt » and the button stays disabled. So "send the patient's real frequency" and "a start date only if given" can't be done without a new design. A3 removes the invented values instead. If onboarding should collect medications, that's a Figma task. When it exists, it should save through `saveDeclaredMedications` (A1), because Spring's step 4 requires a `startDate` (`@NotNull`) and drops the frequency.
2. **The Ma Santé and family-member cards show no medical data**, before and after A3. Their display reads `user.medicalInfo` / `bloodGroup`, which the app never fills, and `_toDetailMember` passes empty values. The editor itself now loads the record. Binding those cards to the record is a display task (proposed for A5 or a follow-up). Meanwhile, check saves in « Dossier médical ».
3. **« Allergie Pénicilline » is no longer a Ma Santé condition chip** (one shared preset list, D2), and Ma Santé has no allergies section, so it can be entered through the record editor's « Allergies » or onboarding. Say if Ma Santé should keep it.
4. **Ma Santé's editor now also shows the OmniCare prescriptions** (read-only Résumé rows) and « Déclaré par le patient » on the patient's rows, because A2's rules say professional items are shown and declared items are labelled.
5. **ADR-012 D6** is still not written in the ADR (see A2 §6.5).
6. **Release blocker (B6/B6b):** doctor-side hiding of non-critical conditions before any real patient (G-1).

## 8. Manual test steps for the CTO

Run `flutter run -d chrome --web-port=53472 --dart-define=OMNICARE_API_BASE_URL=http://localhost:8080`, with Spring and MRS running.

1. **Onboarding (new account).** Sign up and start onboarding.
   - **Body page:** choose O+, 172 cm, 70 kg, and continue. The wheels only allow 30–299 cm and 1–499 kg, so the new range check is a safety net, tested in code.
   - **Allergies:** answer « Oui » without typing a name and tap « Continuer »: « Indiquez le nom de l'allergie. ». Type « Lactose » and continue.
   - **Conditions:** answer « Oui » without choosing and tap « Continuer »: « Choisissez au moins une maladie, ou répondez « Non ». ». Choose « Asthme » and continue.
   - **Medications:** answer « Non » and finish.
2. Open « Dossier médical ». It shows O+, 172 cm / 70 kg, the allergy « Lactose », the condition « Asthme » (in French, not « Asthma »), and « Aucun traitement… ».
3. **Ma Santé.** Open « Ma Santé » → « Modifier Mes Données ».
   - The screen loads your record: O+, « Asthme » selected.
   - Choose « Je ne sais pas » in the blood type list. Select « Migraine ».
   - Tap « Ajouter » under medications and type « Vitamine D » (no list needed), « 1000 UI », « 1x/jour ». The row shows « Déclaré par le patient ».
   - Tap « Enregistrer les Modifications »: the screen closes, and no « ne peuvent pas encore être enregistrés » message shows.
   - In « Dossier médical » you see « Non renseigné » for the blood type, « Asthme » and « Migraine », and « Vitamine D » with « Déclaré par le patient ».
4. **Wrong values in Ma Santé.**
   - Fréquence « matin et soir » → « Entre 1 et 6 prises par jour. » under the field.
   - An empty medication name → « Ce champ est obligatoire. ».
   - Nothing is lost.
5. **MRS down in Ma Santé.**
   - Open the editor, then run `cd ~/Desktop/omnicare/omnicare-mrs && docker compose stop mrs-api`. Select « Arthrite » and save.
   - A red message « Le dossier médical est temporairement indisponible… » appears with « Réessayer », and « Arthrite » stays selected.
   - Run `docker compose start mrs-api`, wait for `healthy`, then tap « Réessayer »: it saves once.
6. **Family member.**
   - Home → family member card → « Modifier ». Choose A-, select « Hypertension », add the medication « Doliprane », « 500 mg », « 2x/jour », and save. The member's detail shows A-, « Hypertension » and the medication.
   - In « Dossier médical », select that member: the same data. Select yourself: your data is unchanged.
7. **Professional item (if your test data has one).** In Ma Santé, a condition recorded by a doctor shows as selected; tapping it shows « Cet élément a été ajouté par un professionnel de santé et ne peut pas être modifié. ». A blood type set by a doctor shows a disabled list.
