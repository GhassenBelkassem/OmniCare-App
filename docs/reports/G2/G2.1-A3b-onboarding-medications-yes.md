# G2.1-A3b — Onboarding medications: « Oui » finishes without a false « Aucun »

Date: 2026-11-13 · Repo: OmniCare-App only · Follows: G2.1-A3 (§3.3, STOP §5.1)

## 1. Decision applied

CTO decision of 2026-11-13: there are no medication fields in onboarding in V1. But « Oui » must never block onboarding, and must never record a false « Aucun ».

| Answer on the medications page | Before (A3) | Now |
|---|---|---|
| « Non » | finish; step 4 `{noKnownMedications:true}` → « Aucun » | unchanged |
| « Oui » | finish button disabled: onboarding blocked | finish enabled; step 4 sent with an **empty body**. It completes onboarding and writes nothing, so the declared list stays **UNKNOWN** (« Non renseigné ») |
| Note under « Oui » | « L'ajout de médicaments sera bientôt disponible » + « Vous pourrez les ajouter depuis votre dossier médical. » | « Vous pourrez ajouter vos médicaments dans votre dossier médical. » (one ARB key, the note's title style) |

**Why an empty step 4:**
- Step 4 is the route that completes onboarding, so it must still be sent.
- Spring writes nothing for a step with neither a list nor « none »: `OnboardingService` case 4, tested by Spring's `noneIsNoneKnownAndASkippedStepStaysUnknown`.
- MRS then reads the never-saved declared list as UNKNOWN (B3 §4).
- No Spring change.

## 4. Manual test steps for the CTO

Run `flutter run -d chrome --web-port=53472 --dart-define=OMNICARE_API_BASE_URL=http://localhost:8080`, with Spring and MRS running.

1. Create a new account and go through onboarding to the « Médicaments » page.
2. Tap « Oui ». The note reads « Vous pourrez ajouter vos médicaments dans votre dossier médical. », and the finish button is enabled.
3. Tap the finish button: onboarding ends and the completion screen shows.
4. Open « Dossier médical » → Résumé → « Médicaments », tab « Actuels ». It reads « Non renseigné », not « Aucun traitement… ».
