## 3. Decisions

1. **`MedicalDocumentsViewModel`** (one, in `main.dart`, cleared on logout with the record):
   - **The person:** `select(subject)` cancels what's in flight, stops every poll, clears the list, and bumps a generation so a late answer is dropped. `ensureLoaded()` reads the first page when the tab is shown.
   - **Upload:** on 202 the document is put first, with the answer's status (SCAN_PENDING), and its status is polled.
   - **Delete:** the row leaves only on 204.
2. **The count:**
   - « {n} documents enregistrés » (plural ARB: « 1 document enregistré »);
   - « {n}+ documents enregistrés » when a next page exists;
   - empty until the list is read.
3. **Upload:**
   - **Checks:** `documentFormErrors` checks, by server field name, before any request:
     - name;
     - date;
     - no file / > 15 Mo / not PDF, JPG or PNG (A1's `fileRefusal`, reused).
   - **Messages:** the A1 French texts on each field.
   - **One key:** one `SaveAttempt` per editor. « Réessayer » (in the failure block, or « Enregistrer » again) sends the same key; any edit makes a new one.
   - **Server refusals:** a 400 with field codes shows on the fields; any other failure shows its French text with « Réessayer ». The editor stays open with everything typed.
4. **The file is never held as bytes in state:**
   - **Mobile/desktop:** `file_picker` gives the path → `PathDocumentSource` (Dio reads it from disk in chunks).
   - **Web:** `file_picker` would put the whole file in memory (`withData`), or give a one-time stream that breaks « Réessayer ». So the web picker (`document_file_picker_web.dart`, `package:web`, already a dependency) keeps the browser `File` handle and streams it in 256 KB slices, a fresh stream on each send.
   - **Web limit:** the browser adapter still assembles the whole request once while sending (A1 §7.1, a platform limit).
5. **Polling:**
   - one document at a time, through its status route; never the list;
   - waits of 2, 4, 8, 16 s, then 30 s (cap);
   - stops on AVAILABLE, SCAN_FAILED, not found, a person switch, logout or dispose;
   - a failed read keeps backing off.
6. **`DocumentPagesController` (viewer logic):**
   - opens a session, then page 1; the next or previous page only when asked;
   - only the current PNG is kept, and it's freed when the page changes or the viewer closes;
   - a 410 gets one silent new session (A1); a second one is a failure;
   - DOCUMENT_NOT_READY and 429 keep their A1 texts.
   - B5: sessions last 5 minutes and the watermark is drawn by MRS; the app adds none.
7. **The row date:** the list has no document date (MRS keeps it encrypted in the description, SB3 §4), only `createdAt`. A row would show the upload date in Tunis time unless the list route returns `documentDate`, a Spring change.

## 5. ⛔ STOP: controls that don't exist on screen (need your decision)

1. **Document row.** The tab has only the header and the empty card; there's no row widget for a document. Without one, the loaded list, its type, date and status (« En cours d'analyse », « Analyse échouée ») can't be shown, and nothing can be tapped to open or delete.
   - **Today:** with documents, the tab shows the true count and no card. The empty card would lie, so it's hidden.
   - **Proposal (reuse, no new look):** the Résumé treatment row (`PassportMedicationRow`), with the document icon of the empty card in its tile, the title, « Analyse · 12 nov. 2026 » as its line, and a status pill (« Disponible », « En cours d'analyse », « Analyse échouée »). The 3 French status texts and the type labels would go to the ARB.
   - Also say whether a « Voir plus » is wanted after 20, or the first page only.
2. **Viewer pages.** `DocumentViewerScreen` has no page area or page control, and its share, download, print and « Ouvrir » buttons do nothing (they must be hidden, D3).
   - **Proposal:** the placeholder area shows the current page PNG, and the two bottom buttons become « Page précédente » / « Page suivante ».
   - **Or:** reuse the clinic full-screen gallery (swipe between pages).
3. **Delete a saved document.** The only « Supprimer ce document » is in the « + » editor, which creates a new document. No screen shows a saved document with a delete action.
   - **Proposal:** in the viewer (one button, with the existing confirmation dialog style of the old documents screen).
   - **Or:** a long-press on the row.

**Ready once you decide:** the logic for list, status, polling, open page by page and delete is built and tested. Wiring each control is a small UI step (A4b).

## 8. Manual test steps for the CTO

Run `flutter run -d chrome --web-port=53472 --dart-define=OMNICARE_API_BASE_URL=http://localhost:8080`, with Spring and MRS (with ClamAV) running. The steps that need a row or a page viewer wait for §5; they are marked ⏳.

1. Open « Dossier médical » → « Documents » on a new account. It reads « 0 documents enregistrés » and « Aucun document médical disponible ».
2. **Upload a PDF.**
   - Tap « + ». Name « Bilan sanguin », type « Analyse », date today (`jj/mm/aaaa`).
   - Tap « Télécharger » and pick a small PDF; its name shows in the file field.
   - Tap « Enregistrer les Modifications ». The editor closes and the tab reads « 1 document enregistré ».
3. **Upload a photo** (JPG or PNG) the same way: « 2 documents enregistrés ».
4. **Wrong values** (each refused before sending; everything typed stays):
   - no name → « Ce champ est obligatoire. »;
   - date tomorrow → « La date ne peut pas être dans le futur. »;
   - 31/02/2026 → « Date non valide. »;
   - no file → « Ce champ est obligatoire. »;
   - a `.docx` → « Format non accepté : PDF, JPG ou PNG. » (the picker hides other types; on web choose « Tous les fichiers »);
   - a 16 MB PDF → « Fichier trop volumineux (15 Mo maximum). ».
5. **MRS down.**
   - Run `cd ~/Desktop/omnicare/omnicare-mrs && docker compose stop mrs-api`. Fill the editor and tap « Enregistrer… »: a French message and « Réessayer » appear under the form, and the fields stay filled.
   - Run `docker compose start mrs-api`, wait for `healthy`, then tap « Réessayer »: the editor closes and the count goes up by one (once).
   - With MRS stopped, open the « Documents » tab after a reload: the failure text and « Réessayer » show.
6. **Family member.** Pick a family member in the header: the count shows **their** documents (0 on a new member). Upload one: their count is 1, and yours is unchanged when you switch back.
7. ⏳ Status: « En cours d'analyse » → available (needs the row, §5.1).
8. ⏳ Open and page through (needs §5.2).
9. ⏳ Delete (needs §5.3).
