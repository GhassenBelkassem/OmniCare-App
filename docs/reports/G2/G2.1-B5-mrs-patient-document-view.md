## 3. Decisions

### 3a. Where holder sessions are stored: the existing table, with one new column
A new table was the obvious choice, but it **would break production**. `claiminventory.ValidateCertifiedSchema` (`claiminventory/repository.go:23-52,54-86`) refuses to run if any table has a column named `mrs_patient_id`, `patient_id` or `account_holder_actor_id` that is not on its certified list. So the practice-patient claim would fail on any new subject-linked table, and fixing that means editing claim code.

Migration **000042** therefore:
- adds `holder_purpose TEXT NULL CHECK IN ('SELF_SERVICE','FAMILY_MANAGEMENT')`;
- replaces the CHECK with `num_nonnulls(access_grant_id, custody_id, holder_purpose) = 1`.

Effects:
- **Professional rows:** still need exactly one of grant or custody (tested).
- **Holder rows:** have neither.
- **Revocation sweeps:** every existing sweep (§2 last row) now also covers holder sessions, with no change.
- **Claim list:** the certified column list stays valid.
- **Column name:** `professional_actor_id` carries the viewing actor, here the holder; the migration comment says so.

The down migration was applied and re-applied by hand on postgres:16: OK.

### 3b. Separate routes, not role dispatch in G-1's handler
The patient routes have their own path segment, `/patient-view-sessions`, in a new handler. G-1's routes and handler are untouched. The router registration test (every handler non-nil) passes, so there are no pattern conflicts.

### 3c. Authorization (same rule as the patient document list, plus purpose)
These checks run on create **and on every page**:
1. **Subject:** it is ACTIVE and its `account_holder_actor_id` is the caller. Otherwise **404**, the same as an unknown or foreign document (R2).
2. **Purpose against subject type:** `SELF_SERVICE` must be on MAIN_USER, `FAMILY_MANAGEMENT` on FAMILY_MEMBER. A mismatch gives 400 `INVALID_INTERNAL_REQUEST`, as in the B2 routes. A session is usable only under the purpose it was opened with.
3. **Document status:**
   - AVAILABLE: opens;
   - UPLOAD_INITIATED, SCAN_PENDING or SCAN_FAILED: **409 `DOCUMENT_NOT_READY`**;
   - DELETE_PENDING, DELETED or foreign: **404**.

### 3d. TTL
- **Rule:** `min(MRS_DOCUMENT_VIEW_TTL, 5 min)`. The default today is **5 minutes**. It is the professional value, never more (`patient_view.go:36,390`).
- **Expiry:** an expired session is marked EXPIRED and gives 410. A revoked session also gives 410, meaning "open a new one".

### 3e. Watermark
- **Text:** `CONSULTE PAR LE TITULAIRE DU COMPTE - 12-11-2026 14:05 - REF 1A2B3C4D`
- **Time:** Africa/Tunis (UTC+1, no DST).
- **Reference:** the first 8 hex characters of the session id.
- **No name, no id, no health value:** MRS holds no names.
- **No accent:** the renderer's bitmap font has no `É` and would leave a gap, so « Consulté » is written without it. A test checks that every character is drawable.
- **Always on:** it is applied to patient pages even if `MRS_WATERMARK_ENABLED=false`. Colour and opacity come from config. The professional `MRS_WATERMARK_INCLUDE_*` flags do not apply.

### 3f. Audit (R7, R9)
- **Pattern:** the professional pattern, unchanged:
  - create: `DOCUMENT_VIEW_SESSION`;
  - each page: `DOCUMENT_PAGE_RENDER` and `MRS_DECRYPT`.
- **References:** actor and role PATIENT, subject, document, session id, `purpose` (SELF_SERVICE or FAMILY_MANAGEMENT) and `scope`.
- **No values** in audit rows or logs.
- **Errors:** the API error writer logs fixed text only. Storage or renderer error strings are never logged, unlike the shared `writeDocumentsServiceError`, which logs `err`.

### 3g. Idempotency (R4)
- **Scoped key:** `Hash("PATIENT_DOCUMENT_VIEW_KEY", actor, subject, key)`, under op `CREATE_PATIENT_DOCUMENT_VIEW_SESSION`.
- **Request hash:** binds the document and the purpose.
- **Retry:** the same key returns the same session and token; the token is encrypted at rest in the replay store, as for professionals.
- **Mismatch:** the same key on another document gives 409 `IDEMPOTENCY_CONFLICT`.

### 3h. Rate limit (R11): ⚠️ P2, not in MRS
The professional path has no per-session limit, so none was added. Spring's patient routes must limit page fetches (SB3). Suggestion: 60 pages per minute per actor, with the existing 429 `TOO_MANY_REQUESTS`.

## 5. Contract per route (MRS internal, signed)

Headers on both routes:
- `X-Actor-Id`, `X-Actor-Role: PATIENT`;
- `X-Purpose: SELF_SERVICE | FAMILY_MANAGEMENT`;
- `X-Scope: FULL_PASSPORT`;
- `X-Subject-Mrs-Patient-Id`, which must equal `{mrsPatientID}`;
- the internal signature.

Any other role, purpose or scope gives 400 `INVALID_INTERNAL_REQUEST` before the service is called.

**1. Open a session:** `POST /internal/mrs/patients/{mrsPatientID}/documents/{documentID}/patient-view-sessions`
- **Request:** header `Idempotency-Key` (required). No body.
- **201** (`Cache-Control: no-store`):
  `{"view_session_id","document_id","mrs_patient_id","page_count","expires_at","view_token"}`

**2. One page:** `GET …/patient-view-sessions/{viewSessionID}/pages/{pageNumber}`
- **Request:** header `X-View-Session-Token: <view_token>`; `pageNumber` runs from 1 to `page_count`.
- **200:** a PNG body with these headers:
  - `Content-Type: image/png`, `Content-Disposition: inline`;
  - `X-Document-Page`, `X-Document-Page-Count`;
  - `Cache-Control: no-store, no-cache, must-revalidate, private, max-age=0`, `Pragma: no-cache`;
  - CSP `sandbox`, `X-Frame-Options: DENY`, `nosniff`, `no-referrer`.

**Close (optional):** the existing `POST …/documents/{documentID}/view-sessions/{viewSessionID}/revoke` already lets the PATIENT holder revoke their session (`view_service.go:336-398`, tested). It is not audited and answers 403 for a non-holder. SB3 may skip it, because sessions die within 5 minutes.

### Error codes (body `{"error":{"code":…}}`, never a value)

| HTTP | Code | When | Route |
|---|---|---|---|
| 400 | `INVALID_INTERNAL_REQUEST` | wrong role/purpose/scope; purpose does not match the subject type | both |
| 400 | `INVALID_IDEMPOTENCY_KEY` | key missing or malformed | 1 |
| 400 | `INVALID_PAGE_NUMBER` | not an integer ≥ 1 | 2 |
| 401 | `VIEW_SESSION_TOKEN_REQUIRED` | no token header | 2 |
| 404 | `DOCUMENT_NOT_FOUND` | unknown, deleted, another record's document, caller not the holder (also when re-checked on a page) | both |
| 404 | `VIEW_SESSION_NOT_FOUND` | unknown session, wrong token, someone else's session, other purpose | 2 |
| 404 | `DOCUMENT_PAGE_NOT_FOUND` | page > `page_count` | 2 |
| 409 | `DOCUMENT_NOT_READY` | UPLOAD_INITIATED, SCAN_PENDING, SCAN_FAILED | both |
| 409 | `IDEMPOTENCY_CONFLICT` / `IDEMPOTENCY_IN_PROGRESS` | key reused for another request / still running | 1 |
| 410 | `VIEW_SESSION_EXPIRED` | expired or revoked: open a new session | 2 |
| 503 | `DOCUMENT_RENDERER_UNAVAILABLE`, `MRS_KEY_UNAVAILABLE`, `AUDIT_UNAVAILABLE` | dependency down | both |
| 500 | `INTERNAL_ERROR` | anything else (fixed log line) | both |

## 6. What SB3 (Spring) must call and map

1. **Patient routes** under `/api/v1/me/medical-record/documents/{documentId}` (FT-1 rules: PATIENT only, `subject=SELF|FAMILY:{familyMemberId}`, `CareSubjectResolver` → MRS id + purpose; the app never sends an MRS id):
   - `POST …/view-sessions` → MRS route 1 with a server-made Idempotency-Key per user action (R4) → `{viewSessionId, pageCount, expiresAt}`. **Keep `view_token` server-side** (store it for the session, keyed by actor+session, TTL ≤ 5 min), or return it in a `no-store` body only if the app must send it back; never log it.
   - `GET …/view-sessions/{id}/pages/{n}` → MRS route 2; stream the PNG with the same no-store headers. **No download route**: `denyRawDownload` stays.
2. **Mapping to the FT-1 envelope:**
   - 404 (any of the three codes) → `RESOURCE_NOT_FOUND`;
   - 409 `DOCUMENT_NOT_READY` → its own code, so the app can show « Document en cours d'analyse »;
   - 410 → `VIEW_SESSION_EXPIRED`, so the app opens a new session silently once;
   - 503 / timeouts → `MRS_UNAVAILABLE` with « Réessayer ».
3. **R8:** call MRS outside any DB transaction. **R10:** PATIENT matchers + CSRF on the POST. **R11:** a page-fetch rate limit per actor (§3h).
4. **Audit:** Spring's own log line `patient_record_read section=DOCUMENT_VIEW subject=… outcome=… code=…` (no token, no title).

## 9. Risks and findings

1. **R11 (P2):** no page-rate limit in MRS (§3h). Spring must add one in SB3.
2. **Migration number:** 000042 follows B3's 000041. If another branch adds either number, renumber at commit.
3. **Column name:** `professional_actor_id` now also holds the holder on holder rows. Any future query that reads this column as "a professional viewed" must filter `holder_purpose IS NULL`. Today no query does: the sweeps revoke by subject, grant or document only.
4. **Duplicated decrypt code:** `decryptViewDocument` duplicates about 20 lines of `renderViewPage` (`view_service.go:285-307`) because G-1's file is read-only. G-1 can extract one shared helper later.
5. **G-1 note (P3, not changed):** `renderViewPage` repeats its status/expiry block twice (`view_service.go:205-273`). It is harmless dead code.
6. **The existing revoke route** (holder close) is not audited and answers 403 rather than 404 for a non-holder. It is G-1 code and optional for SB3.
