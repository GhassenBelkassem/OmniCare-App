### 2c. How errors map today
- `GlobalExceptionHandler` turns an `ApiException` into the shared envelope `{code, message, timestamp, fieldErrors, fieldErrorCodes?}`.
- Bean Validation turns into 400 `VALIDATION_ERROR` with `fieldErrorCodes` from `FieldErrorCode.of` (1b-2b).
- `MRS_UNAVAILABLE` adds `Retry-After: 30`.
- The envelope had **no** `currentVersion` field. So the 409 version conflict uses a controller-local handler (§3d), and `ErrorResponse` is unchanged.

### 2d. CSRF posture (R10): ✅ not applicable, no P1
- Authentication is a **bearer token in the `Authorization` header only** (`OpaqueTokenAuthenticationFilter.java:50-51`).
- The session policy is STATELESS, and there is no cookie session (`AuthWebSecurityConfig.java:38-43`).
- A browser never attaches the token by itself, so cross-site request forgery has nothing to ride on. `csrf().disable()` is correct here.
- CORS is the existing allow-list.
- **If a cookie session is ever added, CSRF becomes P1.**

## 3. Decisions

### 3a. Routes and security
- **Controller:** a new `PatientMedicalRecordWriteController` with the same base path and `@PreAuthorize("hasRole('PATIENT')")`.
- **Matchers:** before this change, PUT under `/api/v1/me/medical-record/**` fell to `anyRequest().denyAll()`. A **PATIENT-only PUT matcher** was added (`AuthWebSecurityConfig.java:184-185`). The GET matcher is unchanged.

### 3b. Validation mirrors MRS exactly
Bean Validation on records, with the limits of B1-B2 §3 and B3 §3.2.

Two small constraints copy the MRS text rule (`normalizePatientText`), so that Spring and MRS refuse the same inputs with the same codes:
- **`@CodePointMax(max)`:** length is counted in code points after trim and NFC. `@Size` counts UTF-16 units and would refuse 160 emoji that MRS accepts (tested).
- **`@NoControlCharacters`:** refuses Cc characters and bidirectional overrides U+202A–E and U+2066–9. ZWJ is allowed, as in MRS.

Everything else uses the standard annotations. Two rules are left to MRS, which answers with the same field names and codes:
- **duplicates:** case-folded, and including labels a professional already recorded;
- **dates:** "not in the future in Africa/Tunis", and impossible calendar dates.

### 3c. Unknown fields → 400 (R1)
- **How:** every request record has a throwing `@JsonAnySetter`, the existing pattern from `HomeHoldWithdrawalRequest`.
- **Result:** `authorType`, `authorId`, `source`, or `severity` on a condition, gives 400 `VALIDATION_ERROR` and MRS is never called (tested for all five routes).
- **No echo:** the field name is not echoed.

### 3d. Version conflict: 409 with `currentVersion` only (R5)
- **Body:** `{code:"RECORD_VERSION_CONFLICT", message, timestamp, fieldErrors:{}, currentVersion:N}`.
- **Same keys** as the shared envelope plus one; tested to have exactly these keys and no submitted value.

### 3e. Idempotency (R4): no second store
- **Header:** `Idempotency-Key` is required and must be a **UUID v4**. It is lower-cased and passed to MRS.
- **Scoping:** MRS already scopes the key to (actor, subject, section) and binds it to the request hash. A Spring copy (`command_receipts`) would only duplicate that, so none was added.
- **Missing key:** `fieldErrorCodes["Idempotency-Key"] = REQUIRED`. **Bad key:** `INVALID_FORMAT`.

### 3f. Subject and purpose (R2, R7)
- **Resolution:** `subject=SELF|FAMILY:{familyMemberId}` goes through the existing `CareSubjectResolver`. The read service and the write service now share one helper, `RecordSubjects.resolve`.
- **Foreign subjects:** a foreign or unknown family member gives the same 404 **before** MRS is called.
- **Purpose:** SELF is sent as `SELF_SERVICE`, a family member as `FAMILY_MANAGEMENT` (`HttpMrsPatientRecordClient.context`). MRS audits with that purpose.

### 3g. Synchronous, outside transactions, no retry (R8)
- The write service is **not** `@Transactional` and Spring stores nothing.
- The only DB access is the resolver's short read in the profile module, which ends before the MRS call.
- MRS-down, timeout or 5xx gives 503 `MRS_UNAVAILABLE` with `Retry-After: 30`. The app's « Réessayer » sends the **same** key.

### 3h. Field codes: final list (`FieldErrorCode`)
`REQUIRED, TOO_SHORT, TOO_LONG, INVALID_FORMAT, OUT_OF_RANGE, INVALID, DUPLICATE`
- **Added:** **`DUPLICATE`**, appended last, so the existing precedence is unchanged.
- **Not added:** **`TOO_MANY_ITEMS`**. A list over 50 already gives `TOO_LONG` on `items` through `@Size`, and the MRS `TOO_MANY_ITEMS` maps to the same code. That keeps one code for one condition, and every existing `@Size` list on other routes keeps answering `TOO_LONG`.
- **`CodePointMax`:** mapped as a length rule (`TOO_LONG`).

**MRS code → API code:**
- `REQUIRED`, `NO_CONTENT`, `ITEMS_REQUIRED` → `REQUIRED`;
- `TOO_SHORT` → `TOO_SHORT`;
- `TOO_LONG`, `TOO_MANY_ITEMS` → `TOO_LONG`;
- `OUT_OF_RANGE` → `OUT_OF_RANGE`;
- `INVALID_DATE` → `INVALID_FORMAT`;
- `DUPLICATE` → `DUPLICATE`;
- `INVALID_VALUE`, `NOT_ALLOWED` and any other code → `INVALID`.

**MRS paths → API paths:** `items.2.dosage_text` → `items[2].dosageText`, the same names Bean Validation uses. `NO_CONTENT` at `""` → `heightCm` and `weightKg` both `REQUIRED`.

### 3i. New error codes (`ErrorCode`, additive)
| Code | Status |
|---|---|
| `RECORD_VERSION_CONFLICT` | 409 |
| `ITEM_LOCKED` | 422 |
| `BLOOD_TYPE_LOCKED` | 422 |

### 3j. The SELF legacy fallback: kept, listed for SB2

## 4. Contract for the app

**Common to every route:**
- **Access:**
  - PATIENT only (a doctor gets 403; no login gets 401);
  - `subject=SELF|FAMILY:{familyMemberId}` (400 `fieldErrorCodes.subject` REQUIRED/INVALID_FORMAT);
  - JSON body; `Cache-Control: no-store`.
- **Writes** also need the header `Idempotency-Key: <UUID v4>`:
  - make a new key per « Enregistrer »;
  - send the **same** key on « Réessayer ».
- **Common errors:**

| HTTP | Code | When |
|---|---|---|
| 401 | `UNAUTHORIZED` | not logged in |
| 403 | `FORBIDDEN` | not a patient |
| 400 | `VALIDATION_ERROR` | `fieldErrors` + `fieldErrorCodes` |
| 404 | `RESOURCE_NOT_FOUND` | foreign or unknown subject, or an `itemId` that is not in the section: the same body in every case |
| 409 | `CLINICAL_SUBJECT_UNAVAILABLE` | the subject has no record yet |
| 503 | `MRS_UNAVAILABLE` | MRS down; `Retry-After: 30` |

### 4a. Writes: `PUT /api/v1/me/medical-record/…`

| Route | Body | 200 |
|---|---|---|
| `life-safety/blood-type` | `{value, expectedVersion}` | `{section:"BLOOD_TYPE", version, warnings:[]}` |
| `life-safety/allergies` | `{items:[{itemId?, label, severity?}], expectedVersion}` | `{section:"ALLERGIES", version, warnings}` |
| `life-safety/conditions` | `{items:[{itemId?, label}], expectedVersion}` | `{section:"CONDITIONS", …}` |
| `body-measurements` | `{heightCm?, weightKg?, expectedVersion}`: at least one | `{section:"BODY_MEASUREMENTS", version, warnings:["HEIGHT_UNUSUAL"?, "WEIGHT_UNUSUAL"?]}` |
| `medications/declared` | `{items:[{itemId?, name, dosageText?, timesPerDay?, duration?{value, unit}, startedOn?}], expectedVersion}` | `{section:"DECLARED_MEDICATIONS", …}` |

**Semantics** (MRS, ADR-012):
- **List PUT:** each list route replaces the patient's **own** items with the list sent:
  - an own item left out is deleted;
  - `itemId` keeps or edits it;
  - an item without `itemId` is new.
- **Professional items:** they are kept by MRS. Sending a professional item's `itemId`, or a prescription id for medications, gives **422 `ITEM_LOCKED`**.
- **Empty list:** `items: []` records « Aucun » (NONE_KNOWN), unless a professional item or a current prescription remains.
- **Blood type:** a blood type set by a professional gives **422 `BLOOD_TYPE_LOCKED`**. `UNKNOWN` records « Je ne sais pas ».
- **`expectedVersion`:** the section's `version` from the last read, or 0 when it was never recorded.
- **Warnings:** they don't block the save; the app may show « Valeur inhabituelle ».

**Write-specific errors:**

| HTTP | Code | Body / meaning |
|---|---|---|
| 409 | `RECORD_VERSION_CONFLICT` | `{…, currentVersion}`: the section changed; reload it, keep what the user typed, then let them save again |
| 409 | `IDEMPOTENCY_CONFLICT` | the key was reused for different content: make a new key |
| 409 | `IDEMPOTENCY_IN_PROGRESS` | the same save is still running: retry shortly with the same key |
| 409 | `MRS_SINGLETON_SERIES_AMBIGUOUS` | the record needs reconciliation (rare; « Réessayer plus tard ») |
| 422 | `ITEM_LOCKED` / `BLOOD_TYPE_LOCKED` | see the semantics above |
| 400 | `VALIDATION_ERROR` | **unknown field** (`authorType`, `authorId`, `source`, …): no `fieldErrorCodes`, `fieldErrors.body` |

**`fieldErrorCodes` per field** (key = API path; `n` = list index):

| Route | Field | Codes |
|---|---|---|
| all | `Idempotency-Key` | `REQUIRED`, `INVALID_FORMAT` |
| all | `expectedVersion` | `REQUIRED`, `OUT_OF_RANGE` (< 0) |
| blood-type | `value` | `REQUIRED`, `INVALID_FORMAT` (not A±, B±, AB±, O± or UNKNOWN) |
| allergies, conditions, medications | `items` | `REQUIRED` (missing), `TOO_LONG` (> 50, professional items included) |
| allergies, conditions, medications | `items[n]` | `REQUIRED` (null entry) |
| allergies, conditions, medications | `items[n].itemId` | `INVALID_FORMAT` (not a UUID), `DUPLICATE` (twice in the list) |
| allergies, conditions | `items[n].label` | `REQUIRED`, `TOO_LONG` (> 160), `INVALID` (control or bidi character), `DUPLICATE` (same label, case-insensitive, also against professional items) |
| allergies | `items[n].severity` | `INVALID_FORMAT` (not MILD, MODERATE or SEVERE; empty = none) |
| body-measurements | `heightCm` | `OUT_OF_RANGE` (< 30 or > 300), `REQUIRED` (both missing) |
| body-measurements | `weightKg` | `OUT_OF_RANGE` (≤ 0 or > 500), `REQUIRED` (both missing) |
| medications | `items[n].name` | `REQUIRED`, `TOO_LONG` (> 160), `INVALID`, `DUPLICATE` |
| medications | `items[n].dosageText` | `TOO_LONG` (> 80), `INVALID` |
| medications | `items[n].timesPerDay` | `OUT_OF_RANGE` (1–6) |
| medications | `items[n].duration.value` | `REQUIRED`, `OUT_OF_RANGE` (1–365) |
| medications | `items[n].duration.unit` | `REQUIRED`, `INVALID_FORMAT` (DAY, WEEK, MONTH), `INVALID` (when MRS refuses it) |
| medications | `items[n].startedOn` | `INVALID_FORMAT` (not YYYY-MM-DD, or an impossible date), `OUT_OF_RANGE` (after today in Africa/Tunis) |

Lengths are counted in characters (code points) after trimming. These are input limits, not dosing rules.

### 4b. Reads (additive; every old field keeps its name, type and meaning)

**`GET …/medical-data?subject=`:**
```
{lifeSafety:{bloodType, allergies[], allergiesStatus, criticalConditions[], conditionsStatus,      ← unchanged
             bloodTypeAuthorType, bloodTypeVersion,                                               ← new
             allergyItems:[{itemId, label, authorType, severity}], allergiesVersion,              ← new
             conditionItems:[{itemId, label, authorType, severity:null}], conditionsVersion},     ← new
 bodyMeasurements:{heightCm, weightKg, bmi, measuredAt,                                           ← unchanged
                   authorType, version}}                                                          ← new
```
- `allergies` / `criticalConditions` are the labels of the items, in the same order.
- `authorType`: PATIENT or PROFESSIONAL. A PROFESSIONAL item is shown but must be read-only in the editor.
- A section never recorded has version 0.

**`GET …/medications?subject=&group=CURRENT|PAST&size=&cursor=`:**
- **Paging:** unchanged. Declared items join their group in the same newest-first keyset.
- **New on each item:** `source` (`PRESCRIPTION` | `PATIENT_DECLARED`), `authorType` (`PROFESSIONAL` | `PATIENT`), `itemId` and `duration{value, unit}`.
- **Declared items:**
  - `medicationStatementId = itemId` (the row identity the app already requires);
  - `consultationId`, the dose fields and `displayStatus` are null;
  - dates are Africa/Tunis dates.
- **New on the page:** `listStatus` (UNKNOWN, NONE_KNOWN or LIST) and `listVersion`. `listVersion` is the `expectedVersion` for `PUT …/medications/declared`.

## 7. Risks and findings

1. **P1 for SB2: `/profile/medical-data` (Ma Santé) will show stale data after a patient save.**
   - `MrsMedicalDataService.read` (`MrsMedicalDataService.java:45-56`) finds the record through Spring's own `mrs_record_references` and parses v1/v2 payloads.
   - A save through these routes creates a new v3 head that Spring never referenced.
   - SB2 must switch Ma Santé and the family screen to `GET /me/medical-record/medical-data` or these routes.
2. **P1 for SB2: the legacy singleton writers still run.** Onboarding and profile still write through the outbox: `UserProfileService.java:94,159`, `FamilyMemberService.java:141` and `MrsOnboardingSyncService.java:35,60,72` (B1-B2 report). They must move to these routes in SB2, before A6.
3. **SB2:** the SELF legacy-column fallback (§3j) goes away once SB2 moves those columns into MRS.
4. **R11:** these routes have no per-route rate limit. The global limits apply. MRS calls are bounded by the 5 s timeout. P2: add a per-actor write limit with the existing 429 if abuse is seen.
5. **Measurement limits:** Spring mirrors the MRS **defaults** (30–300 cm, 500 kg). If ops narrows `MRS_MEASUREMENT_*`, MRS refuses with the same codes, so the app still gets a correct message, from MRS instead of Spring.
6. **`heightCm`** in the read stays whole centimetres (truncated, as before), even if a decimal height was saved.
