## 3. Navigation: why no sheet stays open

- **Post-login:** the moved code still calls `navigateAfterAuthentication(context, auth)`, with the **sheet's** context. That function ends with `Navigator.of(context).pushNamedAndRemoveUntil(route, (_) => false)`. The sheet is a route on the same (root) navigator as the welcome screen, so that one call removes both. **The final stack equals today's:** only the destination route.
- **Same for the other exits:** the account-link « linked » path (`navigateAfterAuthentication`) and the unsupported-role path (`pushNamedAndRemoveUntil('/login', …)`).
- **Why not close the sheet first:** the moved logic must stay verbatim, and `pushNamedAndRemoveUntil` already removes everything.
- **Dismissal guard:** the moved logic stops at `if (!mounted) return;` after each `await`. If the sheet closed mid-request, a successful login would never navigate. So:
  - `PopScope(canPop: !_loading && !auth.isAuthenticated)` refuses back and taps above the sheet while signing in, and once authenticated until the navigation lands.
  - **Drag-to-close is off** (`enableDrag: false`). Flutter's drag-close calls `Navigator.pop` directly (`bottom_sheet.dart:724-726`), which `PopScope` cannot refuse.
- **Pending flows** (OTP login, phone login, Google sign-up phone, account-link sheet) are pushed **on top of the sheet**, from the sheet's context as in the moved code. Back from them returns to the sheet with the fields still filled (today: back to the login screen, fields filled). After success, the stack is the same as today.
- **Sheet footer « Créer un compte »:** closes the sheet, then pushes `SignupScreen` on the same navigator, so the stack is `login → sign-up` as today.
- **`/professional-login`:** `LoginScreen.didChangeDependencies` checks `ModalRoute.settings.name == '/professional-login'` once and opens the sheet in a post-frame callback. `/login` and `/auth-entry` show the welcome screen only.

# P2a-fix — after the CTO's visual test (2026-11-12)

Logic unchanged: same controller calls, order, navigation and validator rules. No git command run.

## A. Causes found

1. **Content centred on the welcome screen.** `ConstrainedBox(minHeight)` → `Center` → `Column(spaceBetween)`. `Center` loosens the constraints, so the minimum height never reached the `Column`. It shrink-wrapped and `Center` put it mid-screen.
2. **No visible press / hover / focus feedback.** There was no `NoSplash`, no transparent `overlayColor`, no `GestureDetector`. Instead:
   - **Welcome buttons:** `styleFrom(overlayColor:)` only gives the faint default layers (pressed 10 %, hover 8 %, focus 10 %; `elevated_button.dart:224-226`). There was no press scale and no hover lift, because the global theme forces `elevation: 0` and a transparent `shadowColor`.
   - **Sheet primary button:** the global theme's `overlayColor` only sets a pressed layer (white 6 %, otherwise `null`), so it had no hover or focus layer at all.
   - **Links:** the `InkWell` painted its ink on the Scaffold's Material, **under** the decorative circles, with the theme splash (freshMint 8 %) on dark teal. It was invisible.
   - **Focus:** no custom focus ring anywhere.
3. **Text looking regular (400) at w500.** The theme's `textTheme` comes from `GoogleFonts.plusJakartaSansTextTheme`. Each style's family name is bound to one weight file (e.g. `PlusJakartaSans_regular`; `google_fonts_family_with_variant.dart:30`), so `copyWith(fontWeight: w500)` still draws the regular face, and w700/w800 get a synthetic bold.
   - That regular face is **not bundled**. `google_fonts` downloads it at runtime from `fonts.gstatic.com`; a test run showed the fetch.
   - **Fix here:** every text on the welcome screen and the login sheet now uses the bundled family `'Plus Jakarta Sans'` (pubspec weights 500–800), as the theme's buttons and app bar already do.
   - **The global `textTheme` is unchanged** (out of scope); it affects the whole app (see §F).
4. **Logo.** `logo.png` is the symbol + « OmniCare » wordmark. A symbol-only asset already exists: `assets/images/app_logo.png` (the `flutter_launcher_icons` source, identical to `assets/icons/app_icon.png`, already under the declared `assets/images/`). **No new asset and no pubspec change.** Its 1024 px canvas has a wide white margin (the symbol is ~51 % of it), so the badge zooms it 1.95× and clips to the circle.
