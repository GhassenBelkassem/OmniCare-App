## 2. Changes

**a) Splash**
- **Background:** `deepTealActive` with the welcome's decorative circles, using the same widget.
- **Brand:** `OmniLogoBadge` at 72 px (semantic label « Logo OmniCare ») and « OmniCare » in 22 w700 white. Both fade in over 200 ms with `easeOut`. With reduced motion there is no fade.
- **Loading:** a small white `CircularProgressIndicator` (24 px, stroke 2.5).
- **Error state:**
  - The condition is the same as before (`initializationCompleted && status == failure`).
  - A white card holds the offline icon, the message and the retry button.
  - The button is an `ElevatedButton` in `OmniPressable`. It keeps the key `splash-retry-session` and the action (`_navigationScheduled = false; initialize()`).
- **Text and colours:**
  - English texts → ARB: `:87` → `splashSessionError`, `:102` → `splashRetry`.
  - Every hardcoded colour was replaced with an Omni token.
  - The old asset fallback icon is gone, since `OmniLogoBadge` has its own.
- **Layout:** the welcome's scroll-safe layout (`LayoutBuilder` side padding, then `SliverFillRemaining`), with a maximum width of 480.

**b) Forced password change (`/change-password-required`)**
- **Frame:** `AuthFlowFrame` with no step bar.
  - Header: « Sécurité du compte », the former AppBar title.
  - No back button; the old screen had none either (`automaticallyImplyLeading: false`).
  - Top-right: the existing logout action, with the same icon, the same tooltip « Se deconnecter » and the same `_logout`.
- **Body:**
  - Title « Changez votre mot de passe » (24 w800).
  - Reason: « Pour la sécurité de votre compte, choisissez un nouveau mot de passe avant de continuer. »
- **Fields:**
  - Three `OmniTextField`s with the same labels, hints, validators and keyboard actions.
  - Each has an eye toggle with the same tooltips, « Afficher » / « Masquer ».
  - `autovalidateMode: onUserInteraction`.
- **Rule chip:** `PasswordRuleChip` « 12 caractères minimum » under the new password. It is idle at first, *met* at 12 or more characters, and *failed* after a submit that is too short.
- **Live confirm:** as in sign-up step 1. Typing in the new password re-validates a non-empty confirmation, and a match shows « Les mots de passe correspondent ».
- **Errors:**
  - A failure (`controller.errorMessage(...)` or the same fallback) now shows in an inline error banner (alert role) in the pinned area, above the button. It replaces the SnackBar.
  - A success keeps the SnackBar and the `/login` navigation, because the screen navigates away at once.
- **Button:** « Mettre à jour », pinned, with `OmniPressable`, haptic feedback and the spinner while `auth.isSubmitting`. The handler is the same `changeRequiredPassword(current, new)`.

**c) Phone step terms**
- **Placement:** `_TermsText` moved from the scrolling body into the pinned bottom area, directly above the main button (12 px gap).
- **Flows:** shown in both sign-up flows (e-mail and Google), never in phone login.
- **Style:**
  - Text is 13 w500 `textSecondary`, line height 1.45, centred.
  - The highlighted words are unchanged (`deepTeal`).
  - There are no links, because no terms or privacy pages exist yet.

**d) All screens**
- The bundled font is « Plus Jakarta Sans » at weights ≥ 500.
- Touch targets are ≥ 44 px: retry 52, header icons 44+, eye toggles 44, debug button 44.
- No overflow at 360×520 or 360×640 at text size 1.3, including with the keyboard open (§4).

## 5. Deviations (reported, not hidden)

1. **Frame overflow guard (`auth_flow_frame.dart`).**
   - With the terms pinned, the bottom area overflowed by 132 px at 360×520 and by 12 px at 360×640, at text size 1.3 with the keyboard open (260 px). The password screen overflowed by 6 px with its error banner.
   - The pinned area now takes **at most half of the panel**. When its content is taller, it scrolls inside itself, starting from the bottom so the button stays visible.
   - In that case, the terms or the banner are only partly visible until the keyboard closes or the user scrolls the pinned area.
   - Nothing changes when the content fits, which covers every screen with the keyboard closed and the P2b steps.
2. **Frame parameters.** Three optional parameters were added: `showBack` (default true), `closeIcon` and `closeTooltip`. Without them, the password screen would show a dead back arrow and an « × » instead of its logout. Existing callers are unchanged.
3. **Circles moved.** `_DecorativeCircles` moved from `login_screen.dart` into a shared widget so splash and welcome use the same code. `login_screen.dart` changed by one import and one line.
4. **Splash builds without localizations.** `test/clinic_phase1_test.dart` (`_appUnderTest`) mounts `SplashScreen` in a `MaterialApp` with no localization delegates. The old splash never needed them, so `OmniLocalizations.of` crashed 5 clinic tests.
   - The splash now uses a nullable lookup (`Localizations.of<OmniLocalizations>`). When it is missing, only the spinner shows.
   - The app itself always installs the delegates (`main.dart`), so users always see the full splash.
   - The alternative is to add the delegates to that test harness, which is another team's file. See Q1.
5. **Debug-only button** « Clear Local Session » (`kDebugMode`) keeps its English text. It is not a fallback and does not ship in release. It was restyled white so it stays visible on the dark background. See Q4.
6. **Password screen texts kept verbatim and hardcoded.** The prompt asks for « same messages », so labels, hints, validator messages, the success SnackBar, the fallback and the tooltips are unchanged. This includes their missing accents: « caracteres », « different », « mis a jour », « Se deconnecter ». Only the new title and reason are in the ARB. See Q2.
7. **Skipped test pins the old title.** `test/auth_phase1_test.dart:3337` expects « Changer le mot de passe ». That test is `skip: true`, so the suite is green, but it would fail if re-enabled, because the prompt asks for the new title. It was not edited. See Q3.
8. **Chip constant.** A private `_passwordMinLength = 12` drives the chip. The validator keeps its literal `12`, so the rule is untouched.
9. **Small alignments with sign-up:**
   - haptic feedback on « Mettre à jour »;
   - eye icon as in sign-up (open eye while hidden). The old screen showed the opposite icon; the tooltips are unchanged.
10. **Terms style:** colour `textTertiary` → `textSecondary` and line height 1.6 → 1.45, as specified.

## 7. Manual checklist (CTO, web + Android)

1. **Splash, normal:** cold start. Expect a dark teal screen with circles, the logo fading in, « OmniCare » and a white spinner, then the welcome screen (`/login`). If you are already signed in, you go to home or onboarding as before.
2. **Splash, offline:** sign in, close the app, turn on airplane mode, reopen. Expect a white card with « Nous n'avons pas pu vérifier votre session… » and « Réessayer ». Turn the network back on and tap « Réessayer »: it continues as before. Try at system text size max.
3. **Reduced motion** (Android "Remove animations" / iOS "Reduce motion"): the logo appears with no fade.
4. **Forced password change:** use a test account the server flags with `mustChangePassword` (e.g. a doctor account reset by an admin).
   - Sign in. Expect « Sécurité du compte », the logout icon top-right, no back arrow, « Changez votre mot de passe » and the reason line.
   - Type a short new password: the chip turns red after « Mettre à jour », and green at 12 characters.
   - Enter a different confirmation, then the matching one: expect « Les mots de passe correspondent ».
   - Use a wrong current password: expect a red inline banner above the button and no SnackBar.
   - Use correct values: expect the green SnackBar and the welcome screen. Sign in with the new password.
   - The logout icon returns to the welcome screen.
5. **Terms pinned, small phone** (360×640 or smaller, large text):
   - E-mail sign-up step 3 and the Google sign-up phone step: the terms sit right above the button with the keyboard closed. With the keyboard open, the button stays visible and the terms scroll in the pinned area.
   - Phone login: no terms.
